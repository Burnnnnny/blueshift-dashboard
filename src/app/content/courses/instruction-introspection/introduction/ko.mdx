# 명령어 내부 검사 (Instruction Introspection)

![Instruction Introspection](/graphics/course-banners/instruction-introspection.png)

명령어 내부 검사(Instruction introspection)는 프로그램이 동일한 트랜잭션 내의 다른 명령어(아직 실행되지 않은 명령어 포함)를 분석할 수 있게 하는 Solana의 강력한 기능입니다. 이를 통해 예를 들어 안전 장치 주입, 동작 검증, 또는 외부 프로그램의 명령어를 자신의 로직에 통합하는 등 다른 명령어에 동적으로 반응하거나 기능을 강화할 수 있습니다.

이는 `Instructions` sysvar라고 불리는 특별한 시스템 계정에 의해 가능해집니다. Sysvar는 Solana 런타임에 의해 유지되는 읽기 전용 계정으로, 프로그램에 내부 상태(예: 시계, 임대료, 에포크 일정 등)를 노출합니다. Instructions sysvar는 특히 현재 트랜잭션의 전체 명령어 목록과 메타데이터 및 직렬화된 데이터를 노출합니다.

Solana가 런타임에 이 정보를 직렬화하는 방법은 다음과 같습니다:

```rust
// First encode the number of instructions:
//  0..2 - num_instructions
//
// Then a table of offsets of where to find them in the data
//  3..2 * num_instructions table of instruction offsets
//
// Each instruction is then encoded as:
//   0..2 - num_accounts
//   2 - meta_byte -> (bit 0 signer, bit 1 is_writable)
//   3..35 - pubkey - 32 bytes
//   35..67 - program_id
//   67..69 - data len - u16
//   69..data_len - data
#[cfg(not(target_os = "solana"))]
fn serialize_instructions(instructions: &[BorrowedInstruction]) -> Vec<u8> {
    // 64 bytes is a reasonable guess, calculating exactly is slower in benchmarks
    let mut data = Vec::with_capacity(instructions.len() * (32 * 2));
    append_u16(&mut data, instructions.len() as u16);
    for _ in 0..instructions.len() {
        append_u16(&mut data, 0);
    }

    for (i, instruction) in instructions.iter().enumerate() {
        let start_instruction_offset = data.len() as u16;
        let start = 2 + (2 * i);
        data[start..start + 2].copy_from_slice(&start_instruction_offset.to_le_bytes());
        append_u16(&mut data, instruction.accounts.len() as u16);
        for account_meta in &instruction.accounts {
            let mut account_meta_flags = InstructionsSysvarAccountMeta::empty();
            if account_meta.is_signer {
                account_meta_flags |= InstructionsSysvarAccountMeta::IS_SIGNER;
            }
            if account_meta.is_writable {
                account_meta_flags |= InstructionsSysvarAccountMeta::IS_WRITABLE;
            }
            append_u8(&mut data, account_meta_flags.bits());
            append_slice(&mut data, account_meta.pubkey.as_ref());
        }

        append_slice(&mut data, instruction.program_id.as_ref());
        append_u16(&mut data, instruction.data.len() as u16);
        append_slice(&mut data, instruction.data);
    }
    data
}
```

즉, 프로그램 내부에서 `Instructions` sysvar 계정을 읽으면 현재 트랜잭션에 포함된 모든 명령어에 접근할 수 있습니다.

원시 바이트를 수동으로 구문 분석할 필요는 없습니다. Solana는 헬퍼 함수를 제공합니다:
- `load_current_index_checked`: 현재 실행 중인 명령어의 인덱스를 반환합니다.
- `load_instruction_at_checked`: 구문 분석되고 역직렬화된 형식으로 인덱스를 사용하여 특정 명령어를 로드할 수 있습니다.

<ArticleSection name="어떻게 작동하나요?" id="how-does-it-work" level="h2" />

각 Solana 명령어는 다음을 포함합니다:
- 대상 프로그램 ID
- 상호 작용하는 계정 (서명자/쓰기 가능 여부와 같은 메타데이터 포함)
- 데이터 페이로드 (일반적으로 구별자(discriminator) + 인수)

그리고 이것이 바로 Instructions sysvar의 `load_instruction_at_checked` 함수가 제공하는 것입니다:
- program_id: 이 명령어가 호출하는 프로그램.
- accounts: 메타데이터가 포함된 관련 계정 목록.
- data: 원시 입력 페이로드 (Anchor 명령어를 검사하는 경우 종종 8바이트 구별자와 매개변수로 시작).

다른 명령어를 안전하고 효율적으로 검사하려면 다음 단계를 따르세요:
- 현재 명령어 인덱스 결정: `load_current_index_checked`를 사용하여 현재 실행 중인 명령어의 인덱스를 찾습니다.
> 명심하세요: 여러분의 명령어가 트랜잭션의 첫 번째(인덱스 0)가 아닐 수 있습니다.

- 분석할 대상 명령어 로드: 인덱스를 사용하여 `load_instruction_at_checked(index)`로 동일한 트랜잭션 내의 다른 명령어(이전, 이후, 또는 특정 위치)를 로드합니다.
> 이는 동작 검증, 예상된 입력 보장, 또는 프로그램 간의 안전한 구성에 유용합니다.

- 악의적인 동작을 방지하기 위한 제약 조건 구축: 명령어 내부 검사는 강력하지만 새로운 공격 표면을 도입합니다. 검사된 명령어가 예상 프로그램을 대상으로 하는지 확인하고, 계정 주소와 데이터가 예상 패턴과 일치하는지 확인하며, 명시적으로 강제되지 않는 한 명령어 순서에 대한 가정을 피해야 합니다.

이러한 예방 조치를 취함으로써 명령어 내부 검사를 안전하게 활용하여 강력하고 구성 가능하며 안전한 Solana 프로그램을 구축할 수 있습니다.

<ArticleSection name="내부 검사를 위한 일반적인 제약 조건" id="common-constraints-for-introspection" level="h2" />

명령어 내부 검사를 사용할 때는 악의적이거나 예상치 못한 동작을 방지하기 위해 엄격한 제약 조건을 적용하는 것이 필수적입니다. 가장 일반적인 안전 장치는 다음과 같습니다:

- 명령어 검증 (Instruction Verification): 명령어의 프로그램 ID와 구별자를 검증하여 올바른 명령어인지 확인합니다. 구별자(일반적으로 명령어 데이터의 첫 1, 4 또는 8바이트)는 호출되는 함수를 고유하게 식별합니다.
> 이 단계는 스푸핑되거나 잘못된 형식이 아닌 의도한 명령어를 검사하고 있는지 확인합니다.

- 변수 검증 (Variable Validation): 구별자 후, 명령어에서 사용하는 중요한 변수를 구문 분석하고 확인합니다. 여기에는 수량, 방향(예: 롱/숏) 또는 ID가 포함될 수 있으며, 이러한 필드가 통합 또는 안전 장치의 예상 로직과 일치하는지 항상 확인해야 합니다.

- 계정 검증 (Account Verification): 명령어 계정의 구조와 신원을 검증합니다. 예상 계정이 특정 위치(예: 서명자, 볼트, 담보)에 나타나는지 확인하고 서명자/쓰기 가능 상태와 같은 역할이 가정과 일치하는지 확인합니다.

이러한 제약 조건을 적용함으로써 프로그램이 유효하고 신뢰할 수 있는 명령어에만 반응하도록 보장하여 로직을 더 견고하고, 구성 가능하며, 안전하게 만듭니다.

트랜잭션 원자성(atomicity)과 함께, 이러한 검사를 통해 동일한 트랜잭션 내의 다른 프로그램 및 명령어와 안전하게 상호 작용할 수 있는 견고하고 구성 가능한 로직을 구축할 수 있습니다.

> 기억하세요, Solana의 트랜잭션은 원자적입니다. 어떤 명령어라도 실패하면 전체 트랜잭션이 롤백됩니다.
