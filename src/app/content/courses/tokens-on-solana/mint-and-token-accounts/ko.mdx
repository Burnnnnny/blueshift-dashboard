# 민트 및 토큰 계정 (Mint and Token Accounts)

이전 섹션에서 말했듯이 `SPL Token` 프로그램의 구성 요소는 계정입니다. 토큰에 대한 모든 정보를 나타내는 민트 계정과 해당 특정 토큰의 소유권에 대한 모든 정보를 나타내는 토큰 계정입니다.

각 고유 민트에는 원장에 해당 토큰의 보유자가 몇 명인지 나타내는 수천 개의 서로 다른 토큰 계정이 있습니다.

이 섹션에서는 이러한 다양한 계정에 대해 더 자세히 설명하겠습니다:

<ArticleSection name="Mint 계정" id="the-mint-account" level="h2" />

Solana의 토큰은 Token 프로그램이 소유한 Mint 계정의 주소로 고유하게 식별됩니다. 이 계정은 특정 토큰에 대한 글로벌 카운터 역할을 하며 다음과 같은 데이터를 저장합니다:
- 공급량(Supply): 토큰의 총 공급량
- 소수점(Decimals): 토큰의 소수점 정밀도
- 민트 권한(Mint authority): 토큰의 새 단위를 생성하여 공급을 늘릴 수 있는 권한이 있는 계정
- 동결 권한(Freeze authority): 토큰 계정의 토큰을 동결하여 전송하거나 소각하는 것을 방지할 수 있는 권한이 있는 계정

데이터는 온체인에서 다음과 같이 보입니다:

```rust
pub struct Mint {
    /// Optional authority used to mint new tokens. The mint authority may only
    /// be provided during mint creation. If no mint authority is present
    /// then the mint has a fixed supply and no further tokens may be
    /// minted.
    pub mint_authority: COption<Pubkey>,
    /// Total supply of tokens.
    pub supply: u64,
    /// Number of base 10 digits to the right of the decimal place.
    pub decimals: u8,
    /// Is `true` if this structure has been initialized
    pub is_initialized: bool,
    /// Optional authority to freeze token accounts.
    pub freeze_authority: COption<Pubkey>,
}
```

### 메타데이터

탐색기와 지갑에서 토큰은 일반적으로 연결된 특정 이름과 이미지 덕분에 식별 가능하고 사람이 읽을 수 있는 형태로 나타납니다.

우리는 그 이름, 기호 및 이미지를 토큰의 `Metadata`라고 합니다. 기본 형태의 `Mint` 계정은 사람이 읽을 수 있는 정보가 첨부되지 않은 32바이트 길이의 공개 키일 뿐이기 때문입니다.

기본적으로 원래 SPL Token 프로그램에서는 토큰에 메타데이터를 직접 설정할 수 없습니다. 이러한 이유로 [Metaplex](https://www.metaplex.com/)와 같은 프로토콜은 모든 토큰이 관련 메타데이터를 가질 수 있는 방법을 제공하기 위해 [MPL-token-metadata](https://github.com/metaplex-foundation/mpl-token-metadata) 프로그램을 개발했습니다.

> Token Extensions 및 [Token2022 프로그램](/ko/courses/token-2022-program)을 사용하면 이것이 완전히 바뀝니다. 메타데이터 확장을 사용하면 민트 계정 자체에 메타데이터를 직접 삽입할 수 있으므로 외부 프로그램이 필요하지 않습니다.

### 대체 불가능 토큰 (Non-fungible Tokens)

토큰의 유틸리티는 특정 토큰을 거버넌스 토큰, 유틸리티 토큰 또는 커뮤니티 토큰으로 만들기로 결정할 수 있는 작성자에게 구체적으로 위임되지만 대체 가능 토큰과 대체 불가능 토큰을 구분하기 위해 따를 수 있는 몇 가지 특성이 있습니다:

대체 불가능 토큰은 다음을 가져야 합니다:
- 고유하므로 공급량 1
- 분할할 수 없으므로 0 소수점
- 동일한 특성을 가진 토큰을 더 추가하면 토큰의 고유성이 "파괴"되므로 민트 권한 없음

기본적으로 Token 프로그램에서 이러한 특성을 강제하는 것은 불가능합니다. 이러한 이유로 `MPL-token-metadata`와 같은 프로그램은 메타데이터에 대한 구현을 제공할 뿐만 아니라 이러한 제약 조건을 강제하고 NFT를 쉽게 생성할 수 있는 구현도 제공합니다.

<ArticleSection name="Token 계정" id="the-token-account" level="h2" />

Token 프로그램은 각 토큰 단위의 개별 소유권을 추적하기 위해 Token 계정을 생성합니다. Token 계정은 다음과 같은 데이터를 저장합니다:
- Mint: Token 계정이 단위를 보유하는 토큰
- Owner: Token 계정에서 토큰을 전송할 권한이 있는 계정
- Amount: Token 계정이 현재 보유하고 있는 토큰 수

데이터는 온체인에서 다음과 같이 보입니다:

```rust
pub struct Account {
    /// The mint associated with this account
    pub mint: Pubkey,
    /// The owner of this account.
    pub owner: Pubkey,
    /// The amount of tokens this account holds.
    pub amount: u64,
    /// If `delegate` is `Some` then `delegated_amount` represents
    /// the amount authorized by the delegate
    pub delegate: COption<Pubkey>,
    /// The account's state
    pub state: AccountState,
    /// If is_native.is_some, this is a native token, and the value logs the
    /// rent-exempt reserve. An Account is required to be rent-exempt, so
    /// the value is used by the Processor to ensure that wrapped SOL
    /// accounts do not drop below this threshold.
    pub is_native: COption<u64>,
    /// The amount delegated
    pub delegated_amount: u64,
    /// Optional authority to close the account.
    pub close_authority: COption<Pubkey>,
}
```

각 지갑은 보유하려는 각 토큰(민트)에 대해 토큰 계정을 가져야 하며 지갑 주소가 토큰 계정 소유자로 설정되어야 합니다. 각 지갑은 동일한 토큰(민트)에 대해 여러 토큰 계정을 소유할 수 있지만 토큰 계정은 소유자가 한 명뿐이며 하나의 토큰(민트) 단위만 보유할 수 있습니다.

<ArticleSection name="Associated Token 계정" id="the-associated-token-account" level="h2" />

Associated Token 계정은 특정 민트 및 소유자에 대한 토큰 계정 주소를 찾는 프로세스를 단순화합니다. Associated Token 계정을 특정 민트 및 소유자에 대한 "기본" 토큰 계정으로 생각하십시오.

Associated Token 계정은 소유자의 주소와 민트 계정의 주소에서 파생된 주소로 생성됩니다. Associated Token 계정은 특정 주소가 있는 토큰 계정일 뿐이라는 점을 이해하는 것이 중요합니다.

여기서 Solana 개발의 핵심 개념인 [Program Derived Address](https://solana.com/docs/core/pda) (PDA)가 도입됩니다. PDA는 미리 정의된 입력을 사용하여 주소를 결정론적으로 파생시켜 계정 주소를 쉽게 찾을 수 있도록 합니다.
