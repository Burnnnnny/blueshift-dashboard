# 명령어 (Instructions) & CPIs

명령어(Instructions)는 Solana 프로그램의 구성 요소로서 수행할 수 있는 작업을 정의합니다. Anchor에서 명령어는 특정 속성과 제약 조건을 가진 함수로 구현됩니다. 이를 효과적으로 사용하는 방법을 알아봅시다.

<ArticleSection name="명령어 구조" id="instruction-structure" level="h2" />

Anchor에서 명령어는 `#[program]` 모듈과 개별 명령어 함수를 사용하여 정의됩니다. 기본 구조는 다음과 같습니다:

```rust
use anchor_lang::prelude::*;

#[program]
pub mod my_program {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>, data: u64) -> Result<()> {
        // 명령어 로직
        Ok(())
    }
}
```

<ArticleSection name="명령어 컨텍스트" id="instruction-context" level="h3" />

모든 명령어 함수는 첫 번째 매개변수로 `Context` 구조체를 받습니다. 이 컨텍스트에는 다음이 포함됩니다:
- `accounts`: 명령어에 전달된 계정들
- `program_id`: 프로그램의 공개 키
- `remaining_accounts`: 컨텍스트 구조체에 명시적으로 정의되지 않은 추가 계정들
- `bumps`: `bumps` 필드는 PDA로 작업할 때 특히 유용한데, PDA 주소를 파생하는 데 사용된 범프 시드를 제공합니다 (계정 구조체에서 파생하고 있는 경우에만).

다음과 같이 접근할 수 있습니다:

```rust
// 계정 접근
ctx.accounts.account_1
ctx.accounts.account_2

// 프로그램 ID 접근
ctx.program_id

// 남은 계정 접근
for remaining_account in ctx.remaining_accounts {
    // 남은 계정 처리
}

// PDA 범프 접근
let bump = ctx.bumps.pda_account;
```

<ArticleSection name="명령어 식별자" id="instruction-discriminator" level="h3" />

계정과 마찬가지로 Anchor의 명령어는 식별자(discriminator)를 사용하여 서로 다른 명령어 유형을 식별합니다. 기본 식별자는 `sha256("global:<instruction_name>")[0..8]`을 사용하여 생성된 8바이트 접두사입니다. 명령어 이름은 snake_case여야 합니다.

<ArticleSection name="커스텀 명령어 식별자" id="custom-instruction-discriminator" level="h3" />

명령어에 대해 커스텀 식별자를 지정할 수도 있습니다:

```rust
#[instruction(discriminator = 1)]
pub fn custom_discriminator(ctx: Context<Custom>) -> Result<()> {
    // 명령어 로직
    Ok(())
}
```

<ArticleSection name="명령어 스캐폴드" id="instruction-scaffold" level="h2" />

명령어를 다양한 방식으로 작성할 수 있습니다. 이 섹션에서는 실제로 명령어를 설정하는 몇 가지 스타일과 방법을 가르쳐 드리겠습니다.

<ArticleSection name="명령어 로직" id="instruction-logic" level="h3" />

명령어 로직은 프로그램의 복잡성과 선호하는 코딩 스타일에 따라 다양한 방식으로 구성될 수 있습니다. 다음은 주요 접근 방식입니다:

1. **인라인 명령어 로직**

간단한 명령어의 경우, 명령어 함수에 직접 로직을 작성할 수 있습니다:

```rust
pub fn initialize(ctx: Context<Transfer>, amount: u64) -> Result<()> {
    // 토큰 전송 로직

    // 토큰 계정 닫기 로직
    
    Ok(())
}
```
2. **별도 모듈 구현**

매우 복잡한 프로그램의 경우, 로직을 별도 모듈로 구성할 수 있습니다:

```rust
// 별도 파일: transfer.rs
pub fn execute(ctx: Context<Transfer>, amount: u64) -> Result<()> {
    // 토큰 전송 로직

    // 토큰 계정 닫기 로직
 
    Ok(())
}

// lib.rs 에서
pub fn transfer(ctx: Context<Transfer>, amount: u64) -> Result<()> {
    transfer::execute(ctx, amount)
}
```

3. **별도 컨텍스트 구현**

더 복잡한 명령어의 경우, 로직을 컨텍스트 구조체의 구현으로 옮길 수 있습니다:

```rust
// 별도 파일: transfer.rs
pub fn execute(ctx: Context<Transfer>, amount: u64) -> Result<()> {
    ctx.accounts.transfer_tokens(amount)?;
    ctx.accounts.close_token_account()?;
 
    Ok(())
}

impl<'info> Transfer<'info> {
    /// 소스에서 대상 계정으로 토큰 전송
    pub fn transfer_tokens(&mut self, amount: u64) -> Result<()> {
        // 토큰 전송 로직

        Ok(())
    }

    /// 전송 후 소스 토큰 계정 닫기
    pub fn close_token_account(&mut self) -> Result<()> {
        // 토큰 계정 닫기 로직

    }
}

// lib.rs 에서
pub fn transfer(ctx: Context<Transfer>, amount: u64) -> Result<()> {
    transfer::execute(ctx, amount)
}
```

<ArticleSection name="명령어 매개변수" id="instruction-parameters" level="h3" />

명령어는 컨텍스트 외에도 매개변수를 받을 수 있습니다. 이 매개변수들은 Anchor에 의해 자동으로 직렬화 및 역직렬화됩니다. 명령어 매개변수의 핵심 사항은 다음과 같습니다:

1. **기본 타입**

Anchor는 모든 Rust 기본 타입과 일반적인 Solana 타입을 지원합니다:

```rust
pub fn complex_instruction(
    ctx: Context<Complex>,
    amount: u64,
    pubkey: Pubkey,
    vec_data: Vec<u8>,
) -> Result<()> {
    // 명령어 로직
    Ok(())
}
```

2. **커스텀 타입**

커스텀 타입을 매개변수로 사용할 수 있지만, `AnchorSerialize` 및 `AnchorDeserialize`를 구현해야 합니다:

```rust
#[derive(AnchorSerialize, AnchorDeserialize)]
pub struct InstructionData {
    pub field1: u64,
    pub field2: String,
}

pub fn custom_type_instruction(
    ctx: Context<Custom>,
    data: InstructionData,
) -> Result<()> {
    // 명령어 로직
    Ok(())
}
```

<ArticleSection name="모범 사례" id="best-practices" level="h3" />

1. **명령어 집중 유지**: 각 명령어는 한 가지 일을 잘해야 합니다. 명령어가 너무 많은 일을 하고 있다면, 여러 명령어로 나누는 것을 고려하세요.

2. **컨텍스트 구현 사용**: 복잡한 명령어의 경우, 컨텍스트 구현 접근 방식을 사용하여 다음을 수행하세요:
   - 코드 정리
   - 테스트 용이성 향상
   - 재사용성 향상
   - 적절한 문서화 추가

3. **에러 처리**: 항상 적절한 에러 처리를 사용하고 의미 있는 에러 메시지를 반환하세요:
```rust
#[error_code]
pub enum TransferError {
    #[msg("Insufficient balance")]
    InsufficientBalance,
    #[msg("Invalid amount")]
    InvalidAmount,
}

impl<'info> Transfer<'info> {
    pub fn transfer_tokens(&mut self, amount: u64) -> Result<()> {
        require!(amount > 0, TransferError::InvalidAmount);
        require!(
            self.source.amount >= amount,
            TransferError::InsufficientBalance
        );

        // 전송 로직
        Ok(())
    }
}
```

4. **문서화**: 명령어 로직을 항상 문서화하세요. 특히 컨텍스트 구현을 사용할 때 더욱 그렇습니다:
```rust
impl<'info> Transfer<'info> {
    /// # 토큰 전송
    /// 
    /// 소스에서 대상 계정으로 토큰 전송
    pub fn transfer_tokens(&mut self, amount: u64) -> Result<()> {
        // 구현
        Ok(())
    }
}
```

<ArticleSection name="교차 프로그램 호출 (CPIs)" id="cross-program-invocations" level="h2" />

교차 프로그램 호출(CPI)은 한 프로그램이 다른 프로그램의 명령어를 호출하는 과정을 말하며, 이는 Solana 프로그램의 구성 가능성(composability)을 가능하게 합니다. Anchor는 `CpiContext`와 프로그램별 빌더를 통해 CPI를 만드는 편리한 방법을 제공합니다.

**참고**: `use anchor_lang::system_program::*;`을 수행하여 메인 anchor 크레이트에서 모든 시스템 프로그램 CPI를 찾을 수 있습니다. SPL 토큰 프로그램과 관련된 CPI의 경우 anchor_spl 크레이트를 가져와서 `use anchor_spl::token::*`을 수행해야 합니다.

<ArticleSection name="기본 CPI 구조" id="basic-cpi-structure" level="h3" />

기본 CPI를 만드는 방법은 다음과 같습니다:

```rust
use anchor_lang::solana_program::program::invoke_signed;
use anchor_lang::system_program::{transfer, Transfer};

pub fn transfer_lamport(ctx: Context<TransferLamport>, amount: u64) -> Result<()> {
    let cpi_accounts = Transfer {
        from: ctx.accounts.from.to_account_info(),
        to: ctx.accounts.to.to_account_info(),
    };
    
    let cpi_program = ctx.accounts.system_program.to_account_info();
    let cpi_ctx = CpiContext::new(cpi_program, cpi_accounts);
    
    transfer(cpi_ctx, amount)?;
    
    Ok(())
}
```

<ArticleSection name="PDA 서명자를 사용한 CPI" id="cpi-with-pda-signers" level="h3" />

PDA 서명이 필요한 CPI를 만들 때는 `CpiContext::new_with_signer`를 사용하세요:

```rust
use anchor_lang::solana_program::program::invoke_signed;
use anchor_lang::system_program::{transfer, Transfer};

pub fn transfer_lamport_with_pda(ctx: Context<TransferLamportWithPda>, amount: u64) -> Result<()> {
    let seeds = &[
        b"vault".as_ref(),
        &[ctx.bumps.vault],
    ];
    let signer = &[&seeds[..]];
    
    let cpi_accounts = Transfer {
        from: ctx.accounts.vault.to_account_info(),
        to: ctx.accounts.recipient.to_account_info(),
    };
    
    let cpi_program = ctx.accounts.system_program.to_account_info();
    let cpi_ctx = CpiContext::new_with_signer(cpi_program, cpi_accounts, signer);
    
    transfer(cpi_ctx, amount)?;
    
    Ok(())
}
```

<ArticleSection name="에러 처리" id="error-handling" level="h2" />

Anchor는 명령어를 위한 강력한 에러 처리 시스템을 제공합니다. 커스텀 에러를 구현하고 명령어에서 처리하는 방법은 다음과 같습니다:

```rust
#[error_code]
pub enum MyError {
    #[msg("Custom error message")]
    CustomError,
    #[msg("Another error with value: {0}")]
    ValueError(u64),
}

pub fn handle_errors(ctx: Context<HandleErrors>, value: u64) -> Result<()> {
    require!(value > 0, MyError::CustomError);
    require!(value < 100, MyError::ValueError(value));
    
    Ok(())
}
```
