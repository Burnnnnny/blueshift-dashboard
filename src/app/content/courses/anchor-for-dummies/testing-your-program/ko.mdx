# 프로그램 테스트 (Testing Your Program)

철저한 테스트는 금전적 손실을 방지하고, 사용자 신뢰를 구축하며, 프로그램이 모든 조건에서 올바르게 동작하도록 보장합니다.

> 메인넷 배포 전에 엄격하게 테스트하세요.

<ArticleSection name="TypeScript 테스트" id="typescript-tests" level="h2" />

TypeScript 테스트는 어차피 dApp 클라이언트를 위해 TypeScript가 필요하기 때문에 가장 일반적인 접근 방식입니다. 이를 통해 테스트와 클라이언트 코드를 동시에 개발할 수 있습니다.

클라이언트 사이드 설정은 [이곳](/ko/courses/anchor-for-dummies/client-side-development)에서 자세히 다루었습니다.

> 모든 Anchor CLI 프로젝트에는 테스트를 위한 TypeScript 파일이 포함된 test 폴더가 있습니다.

TypeScript 테스트의 주요 장점:
- 실제 클라이언트 상호 작용 반영
- 복잡한 워크플로우 및 엣지 케이스 테스트
- API 변경에 대한 즉각적인 피드백 제공
- 성공 및 에러 시나리오 검증

다음 명령어로 테스트를 실행하세요:

```bash
anchor test
```

> 구성을 localnet으로 설정하여 로컬넷에서 실행하세요. 이렇게 하면 로컬 검증인이 실행되고 공급자 지갑에 1,000 SOL이 추가됩니다. 데이터가 포함된 추가 계정이 필요한 경우 [로컬 검증인 실행](/ko/courses/anchor-for-dummies/testing-your-program#running-a-local-validator)을 참조하세요.

<ArticleSection name="Mollusk 테스트" id="mollusk-tests" level="h2" />

테스트 환경에 대한 세부적인 제어나 복잡한 프로그램 상태 설정이 필요할 때, Mollusk가 해결책을 제공합니다.

Mollusk는 Solana 프로그램을 위해 특별히 제작된 Rust 테스트 프레임워크입니다. 다음과 같은 기능을 제공합니다:
- 네트워크 오버헤드 없이 프로그램 로직을 격리하여 테스트
- 복잡한 계정 상태를 쉽게 설정
- 전체 통합 테스트보다 빠르게 테스트 실행
- 특정 블록체인 조건 및 엣지 케이스 모의(Mock)

Mollusk 테스트는 [이곳](/ko/courses/testing-with-mollusk)에서 철저히 다루었습니다.

Mollusk를 사용하여 새 Anchor 프로그램을 생성하세요:

```bash
anchor init <name-of-the-project> --test-template mollusk
```

테스트 실행:

```bash
anchor test
```

<ArticleSection name="LiteSVM 테스트" id="litesvm-tests" level="h2" />

Mollusk처럼 프로그램 상태에 대한 세부적인 제어가 필요하지만 Typescript 환경을 원할 때, LiteSVM이 최적의 솔루션을 제공합니다.

LiteSVM은 테스트 프로세스 내에서 Solana 가상 머신(VM)을 직접 실행하는 경량 테스트 프레임워크입니다. 다음과 같은 기능을 제공합니다:
- `solana-program-test`와 같은 전통적인 프레임워크보다 훨씬 빠르게 테스트 실행
- 계정 상태 및 sysvars를 정밀하게 조작
- TypeScript, Rust, Python 등 다양한 언어에 걸친 테스트
- 복잡한 블록체인 조건 및 엣지 케이스를 손쉽게 모의(Mock)

LiteSVM은 VM을 테스트 내에 내장하여 검증인 오버헤드를 제거함으로써, 테스트 정확성을 희생하지 않고 빠른 개발 주기에 필요한 속도를 제공합니다.

LiteSVM 테스트는 [이곳](/ko/courses/testing-with-litesvm)에서 철저히 다루었습니다.

`anchor-litesvm` 패키지를 사용하여 Anchor 공급자를 설정하고 [이전](/ko/courses/anchor-for-dummies/client-side-development)에 본 클라이언트 사이드 설정을 사용할 수 있습니다.

`anchor-litesvm` 패키지를 설치하세요.

```bash
npm install git:https://github.com/LiteSVM/anchor-litesvm
```

그런 다음 기본 Anchor 공급자를 다음과 같이 `LiteSVMProvider`로 변경하세요:

```ts
import { fromWorkspace, LiteSVMProvider } from "anchor-litesvm";

test("anchor", async () => {
	const client = fromWorkspace("target/types/<program-name>.ts");
	const provider = new LiteSVMProvider(client);
	const program = new Program<Puppet>(IDL, provider);

    // program.methods..
})
```

<ArticleSection name="로컬 검증인 실행" id="running-a-local-validator" level="h2" />

개인 블록체인 샌드박스 역할을 하는 검증인을 사용하여 로컬에서 메인넷 동작을 반영하세요. 클러스터를 localnet으로 설정하면 자동으로 발생합니다.

로컬 검증인은 네이티브 프로그램이 미리 설치된 단순화된 Solana 원장을 운영합니다. 기본적으로 테스트 데이터만 저장하며 기존 메인넷 계정에 액세스할 수 없어, 기존 프로토콜과의 테스트가 제한됩니다.

### 로컬 검증인 구성

`Anchor.toml`의 `[test]` 섹션에서 검증인을 사용자 정의하세요:

```
[test]
startup_wait = 10000
```

`startup_wait` 플래그는 검증인 시작을 지연시킵니다. 로드 시간을 증가시키는 여러 계정을 복제할 때 유용합니다.

### 메인넷 계정 복제

`[test.validator]` 구성을 사용하여 기존 메인넷 계정과 프로그램을 복제하세요:

```
[test.validator]
url = "https://api.mainnet-beta.solana.com"

[[test.validator.clone]]
address = "7NL2qWArf2BbEBBH1vTRZCsoNqFATTddH6h8GkVvrLpG"
[[test.validator.clone]]
address = "2RaN5auQwMdg5efgCaVqpETBV8sacWGR8tkK4m9kjo5r"
[[test.validator.clone]]
address = "metaqbxxUerdq28cj1RbAWkYQm3ybzjb6a8bt518x1s"
```

`clone` 섹션은 지정된 클러스터에서 계정을 복사합니다. 계정이 "BPF 업그레이드 가능 로더"에 의해 관리되는 프로그램에 연결되면, Anchor는 자동으로 관련 프로그램 데이터 계정도 복제합니다.

### 로컬 계정 데이터 로드

`account` 플래그를 사용하여 JSON 파일에서 로컬 계정을 로드하세요:

```
[[test.validator.account]]
address = "Ev8WSPQsGb4wfjybqff5eZNcS3n6HaMsBkMk9suAiuM"
filename = "some_account.json"
```

이 접근 방식은 사전 구성된 계정 상태나 메인넷에 존재하지 않는 특정 구성으로 테스트할 때 잘 작동합니다.

<ArticleSection name="Surfnet 실행" id="running-surfnet" level="h2" />

교차 프로그램 호출(CPI)에 의존하는 Solana 프로그램을 테스트하려면 전통적으로 개발자가 로컬 검증인 섹션에서 본 것처럼 메인넷에서 계정과 프로그램을 덤프해야 했습니다.

이 과정은 몇 개의 계정에는 효과가 있지만, 40개 이상의 계정과 8개 이상의 프로그램에 의존할 수 있는 Jupiter와 같은 복잡한 프로그램에 CPI를 테스트할 때는 완전히 실행 불가능해집니다.

Surfnet은 개발자가 온디맨드로 가져온 메인넷 계정을 사용하여 로컬에서 프로그램을 시뮬레이션할 수 있게 해주는 solana-test-validator의 드롭인 대체품입니다.

사용하려면 공식 [설치 페이지](https://docs.surfpool.run/install)를 사용하여 surfpool을 설치한 다음 실행하세요:

```bash
surfpool start
```

이제 로컬 검증인을 대상으로 하여 Surfnet에 연결할 수 있습니다:

```ts
import { Connection } from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");
```

Surfnet 설정 및 사용법은 [이곳](/ko/courses/testing-with-surfpool)에서 철저히 다루었습니다.
