# Token2022 프로그램 (The Token2022 Program)

![Token 2022 Program](/graphics/course-banners/token-2022-program.png)

Token Extensions라고도 알려진 Token2022 프로그램은 Token 프로그램이 제공하는 기능의 상위 집합입니다.

레거시 Token 프로그램은 간단하고 불가지론적인 인터페이스와 구조 세트를 통해 대체 가능 및 대체 불가능 토큰에 대한 대부분의 요구 사항을 충족합니다. 그러나 개발자가 공통 인터페이스로 사용자 지정 동작을 생성하여 개발을 더 빠르고 안전하게 만드는 데 도움이 되는 더 독선적인 기능과 구현이 부족합니다.

바로 이러한 이유로 `Token Extensions`라는 새로운 기능 세트를 갖춘 `Token2022`라는 새로운 Token 프로그램이 만들어졌습니다. 이러한 확장은 `Token 계정` 또는 `Mint 계정`에 연결할 수 있는 구체적이고 사용자 지정 가능한 동작을 제공합니다.

> `SPL-Token 프로그램` (개발자들은 일반적으로 프로그램 주소: `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` 때문에 `Tokenkeg`라고 부름)과 `Token2022 프로그램`은 같은 "시작점"을 공유하는 완전히 다른 두 프로그램입니다. 즉, `Tokenkeg` 토큰은 `Token2022`로 역직렬화할 수 있지만 해당 프로그램 내에서 사용하여 확장을 추가하는 등의 작업은 할 수 없습니다.

<ArticleSection name="Mint 및 Token 계정" id="mint-and-token-accounts" level="h2" />

이전 섹션에서 `Tokenkeg`와 `Token2022` 프로그램의 주요 차이점은 **토큰 확장(Token Extensions)**이라는 점에 대해 이야기했습니다.

이러한 확장이 시행되려면 `Mint` 및 `Token` 계정 내부에 직접 존재해야 합니다. 이것이 토큰 프로그램에서 직접 작업하는 동안 규칙 세트가 시행되도록 보장하는 유일한 방법이기 때문입니다.

이러한 이유로 이 계정에서 레거시 토큰 프로그램과 새 토큰 프로그램 간의 주요 차이점을 살펴보겠습니다.

**레거시 토큰 계정**

```rust
#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Mint {
    /// Optional authority used to mint new tokens. The mint authority may only
    /// be provided during mint creation. If no mint authority is present
    /// then the mint has a fixed supply and no further tokens may be
    /// minted.
    pub mint_authority: COption<Pubkey>,
    /// Total supply of tokens.
    pub supply: u64,
    /// Number of base 10 digits to the right of the decimal place.
    pub decimals: u8,
    /// Is `true` if this structure has been initialized
    pub is_initialized: bool,
    /// Optional authority to freeze token accounts.
    pub freeze_authority: COption<Pubkey>,
}

#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Account {
    /// The mint associated with this account
    pub mint: Pubkey,
    /// The owner of this account.
    pub owner: Pubkey,
    /// The amount of tokens this account holds.
    pub amount: u64,
    /// If `delegate` is `Some` then `delegated_amount` represents
    /// the amount authorized by the delegate
    pub delegate: COption<Pubkey>,
    /// The account's state
    pub state: AccountState,
    /// If `is_native.is_some`, this is a native token, and the value logs the
    /// rent-exempt reserve. An Account is required to be rent-exempt, so
    /// the value is used by the Processor to ensure that wrapped SOL
    /// accounts do not drop below this threshold.
    pub is_native: COption<u64>,
    /// The amount delegated
    pub delegated_amount: u64,
    /// Optional authority to close the account.
    pub close_authority: COption<Pubkey>,
}
```

보시다시피, 이 계정에는 작성된 구별자가 없습니다. 필드는 모두 고정 길이이고 공간의 차이가 길이만 비교하여 이러한 다른 유형의 계정을 구별할 수 있을 만큼 충분히 크기 때문입니다.

토큰 확장 프로그램의 문제는 확장에 필요한 추가 데이터가 우리에게 익숙한 `Mint` 및 `Token` 계정의 끝에 태그된다는 것입니다.

즉, `Token` 계정의 길이를 초과하는 3-4개의 확장이 연결된 `Mint`를 가질 수 있기 때문에 길이로 구별하는 것은 부족합니다. 이러한 이유로 `Mint` 및 `Token` 계정에 확장이 있는 경우 다음과 같이 구별자가 추가됩니다:

```rust
#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Mint {
    /// Legacy Token Program data
    /// ...
    /// Padding (83 empty bytes)
    pub padding: [u8; 83]
    /// Discriminator (1)
    pub discriminator: u8
    /// Extensions data
    /// ...
}

#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Account {
    /// Legacy Token Program data
    /// ...
    /// Discriminator (2)
    pub discriminator: u8
    /// Extensions data
    /// ...
}
```

레거시 구조를 유지하기 위해 구별자는 평소와 같이 첫 번째 바이트에 있지 않고 바이트 `166`에 있습니다.

이는 `Token` 계정 길이가 165바이트이기 때문입니다. 즉, 구별자가 기본 길이 뒤에 추가됩니다. `Mint` 계정의 경우 두 계정의 기본 길이가 같도록 83바이트의 패딩을 추가해야 했습니다.

따라서 두 계정을 구별하려면 166번째 바이트(0부터 세는 경우 data[165])를 확인하고 그에 따라 이동하기만 하면 됩니다.

<ArticleSection name="토큰 확장" id="token-extensions" level="h2" />

다음 섹션에서는 현재 Solana에 존재하는 장점과 다양한 토큰 확장에 대해 이야기하겠지만, 이 소개 단락에서는 직렬화되어 이전에 이야기한 두 가지 상태 계정에 추가되는 방법에 대해서만 이야기하겠습니다.

각 확장에는 해당 확장의 크기와 함께 계정에 직접 저장되는 구별자가 있습니다. 우리는 이것을 확장의 "헤더"라고 부르며 다음과 같습니다:

```rust
pub struct ExtensionHeader {
    /// Extension Discriminator
    pub discriminator: u16
    /// Length of the Disriminator
    pub length: u16
}
```

이렇게 하면 토큰에 어떤 확장이 있는지 알고 필요한 확장의 데이터만 역직렬화하기가 매우 쉽습니다. 구별자를 잡은 다음 다음 확장으로 이동하여 무엇이 있는지 확인할 수 있기 때문입니다.
