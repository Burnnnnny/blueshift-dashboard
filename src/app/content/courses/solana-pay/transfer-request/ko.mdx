# 전송 요청 (Transfer Requests)

전송 요청은 서버 상호 작용 없이 간단한 SOL 또는 SPL 토큰 전송을 위해 설계된 Solana Pay의 가장 간단한 결제 방법입니다. 사용자가 QR 코드를 스캔하거나 전송 요청 링크를 클릭하면 지갑은 트랜잭션을 즉시 구성하고 실행하는 데 필요한 모든 것을 갖습니다.

전송 요청의 아름다움은 단순함에 있습니다: 모든 결제 정보가 URL에 직접 인코딩되어 완전히 독립적이고 즉시 실행 가능합니다.

<ArticleSection name="URL 구조 및 파라미터" id="url-structure" level="h2" />

전송 요청 URL은 모든 Solana 지갑이 해석할 수 있는 표준화된 형식을 따릅니다:

```
solana:<recipient>?<optional-query-params>
```

**필수 파라미터:**
- `recipient`: 목적지 지갑을 나타내는 base58 인코딩 공개 키입니다. 이는 유일한 필수 필드이며 중개인 없이 고객에서 가맹점으로 직접 결제가 이루어지도록 합니다.

**선택 파라미터:**
- **`amount`**: 정확한 전송 금액을 십진수 값으로 지정합니다. 이것이 없으면 지갑은 사용자에게 금액을 수동으로 입력하라고 정중하게 요청합니다. 기부 또는 유연한 결제 시나리오에 적합합니다.
- **`spl-token`**: SPL 토큰 전송을 위한 민트 주소입니다. SOL 전송을 USDC 결제에서 맞춤형 로열티 토큰에 이르기까지 모든 토큰 전송으로 변환합니다.
- **`reference`**: 온체인에서 결제를 추적하기 위한 고유 식별자입니다. 가맹점은 트랜잭션 서명을 제어하지 않으므로 참조는 결제 조정 및 고객 지원을 위한 검색 가능한 식별자 역할을 합니다.
- **`label` 및 `message`**: 결제 상황을 설명하는 사용자 대면 문자열입니다. 라벨은 일반적으로 가맹점을 식별하고 메시지는 특정 구매를 설명합니다.
- **`memo`**: Solana의 메모 프로그램을 사용하여 온체인 기록을 생성합니다. 규정 준수, 회계 또는 영구적인 트랜잭션 컨텍스트를 제공하는 데 유용합니다.

### 예제

다음은 실용적인 파라미터 사용법을 보여주는 1 SOL에 대한 전송 요청입니다:

```
solana:22222222222222222222222222222222222222222222?amount=1&label=Blueshift%20Subscription&message=1%20Month&memo=Order12345&reference=abc123def456
```

스테이블코인을 허용하는 비즈니스의 경우 다음은 USDC 전송 요청입니다:

```
solana:22222222222222222222222222222222222222222222?amount=200&spl-token=EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v&label=Blueshift%20Subscription&message=1%20Month&memo=Order12345&reference=abc123def456
```

<ArticleSection name="전송 요청을 사용해야 할 때" id="when-to-use" level="h2" />

전송 요청은 결제 세부 정보가 미리 결정되어 있고 변경되지 않는 시나리오에서 탁월합니다:

**완벽한 사용 사례:**
- 고정 가격의 **전자 상거래 체크아웃**
- 사용자가 금액을 선택하는 **기부 캠페인**
- 알려진 금액의 **구독 결제**
- 대면 거래를 위한 **POS 시스템**
- 특정 금액의 **인보이스 결제**

**주요 이점:**
- **비대화형 특성:** 한 번 생성되면 이러한 URL은 서버와 독립적으로 작동합니다. 네트워크 연결이 불안정할 수 있거나 인프라 의존성을 최소화하려는 상황에 적합합니다.
- **실행 보장:** 결제 파라미터가 URL에 잠겨 있으므로 고객이 동적 가격 변경 없이 귀하가 기대하는 정확한 금액을 지불하도록 보장합니다.
- **오프라인 기능:** POS 단말기와 같은 장치에서 로컬로 URL을 생성할 수 있어 백엔드 시스템을 일시적으로 사용할 수 없더라도 결제가 가능합니다.
- **서버 부하 감소:** 결제 처리 중 API 호출이 필요하지 않아 대용량 시나리오에 매우 확장 가능합니다.
- **보편적 호환성:** 모든 Solana 지갑은 지갑별 통합 없이 이러한 요청을 처리할 수 있습니다.

보장된 결제 금액이 필요하거나 서버 의존성을 줄이고 싶거나 모든 네트워크 조건에서 안정적으로 작동하는 결제 방법이 필요한 경우 전송 요청을 고려하십시오.
