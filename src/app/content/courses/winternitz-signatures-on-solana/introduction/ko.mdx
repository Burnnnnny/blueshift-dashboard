# Solana의 Winternitz 서명 (Winternitz Signatures on Solana)

![Winternitz Signatures on Solana](/graphics/course-banners/winternitz-signatures-on-solana.png)

정수 분해나 이산 로그와 같은 수학적 문제에 의존하여 양자 공격에 취약한 RSA 또는 ECDSA 서명과 달리, Winternitz 서명은 암호화 해시 함수의 단방향 속성에서만 보안을 파생합니다.

이 근본적인 차이는 이것을 포스트 퀀텀(Post-Quantum) 암호학의 초석으로 만듭니다.

<ArticleSection name="Winternitz 서명이란 무엇인가" id="what-is-a-winternitz-signature" level="h2" />

Winternitz One-Time Signatures (WOTS)는 1970년대 Leslie Lamport의 획기적인 작업에서 발전했습니다. Lamport는 복잡한 수학적 가정 없이 암호화 해시 함수만을 사용하여 디지털 서명을 만들 수 있음을 보여주었습니다.

Lamport의 원래 체계는 두 개의 비밀 값을 사용하여 단일 비트에 서명했습니다. 비트 `b`에 서명하려면 해시 값 `H₀`(b=0인 경우) 또는 `H₁`(b=1인 경우)의 원형(preimage)을 공개합니다. 보안은 해시 원형을 찾는 것의 계산적 불가능성, 즉 해시 출력에서 입력으로 역방향으로 작업하는 것이 어렵다는 점에 전적으로 의존했습니다.

그러나 Lamport 서명은 매우 비효율적이었습니다. `n-bit` 메시지에 서명하려면 `2n`개의 비밀 값 필요했고 `2n`개의 값 서명을 생성했습니다. 256비트 메시지의 경우 512개의 비밀 값을 관리하고 512개의 값 서명을 생성하는 것을 의미했습니다.

Robert Winternitz는 1990년대에 2진수로 개별 비트에 서명하는 대신 16진수 또는 256진수와 같은 더 높은 진수로 더 큰 "숫자"에 서명할 수 있다는 것을 깨달았습니다. 이 혁신은 동일한 보안 보장을 유지하면서 키와 서명 크기를 모두 획기적으로 줄였습니다.

<ArticleSection name="수학적 기초" id="mathematical-foundations" level="h2" />

### Winternitz 매개변수 및 기본 표현

Winternitz 서명의 결정적인 매개변수는 `w`이며, 이는 메시지 비트를 그룹화하는 방법을 결정합니다:
- 진수(Base): `b = 2^w`
- 숫자 범위: 각 숫자는 `w` 비트를 나타내며 `0`에서 `2^w - 1`까지의 값을 가질 수 있습니다.

일반적인 매개변수 선택:
- `w = 1`: 각 위치는 1비트(값 0 또는 1)를 나타내며, 2진수의 Lamport 서명과 동일합니다.
- `w = 4`: 각 위치는 4비트(값 0-15)를 나타내며, 16진수 표현입니다.
- `w = 8`: 각 위치는 8비트(값 0-255)를 나타내며, 256진수 표현입니다.

> 더 큰 `w` 값은 더 작은 서명을 생성하지만 보안을 위해 더 많은 계산이 필요합니다. 이 트레이드 오프는 WOTS 성능 특성을 이해하는 데 필수적입니다.

### 해시 체인 (Hash Chains)

Winternitz 서명은 비밀 값에서 시작하여 반복된 해시 적용 시퀀스인 해시 체인을 사용합니다: `H⁰(s) = s`, `H¹(s) = H(s)`, `H²(s) = H(H(s))`, ..., `Hⁱ(s) = H(H^(i-1)(s))`

보안 속성은 비대칭입니다. `Hⁱ(s)`가 주어지면 `j > i`인 `Hʲ(s)`를 계산하는 것은 쉽지만(단지 `j-i`번 더 해시하면 됨), `j < i`인 `Hʲ(s)`를 계산하는 것은 해시 함수를 역전시켜야 하므로 계산적으로 불가능합니다.

### 체크섬 메커니즘 (Checksum Mechanism)

체크섬 메커니즘은 특정 유형의 위조 공격을 방지합니다. 이것이 없으면 서명을 본 공격자는 일부 체인에서 더 많은 해시 작업이 필요한 메시지로 잠재적으로 수정할 수 있고 해당 구성 요소를 위조할 수 있습니다.

체크섬은 모든 체인의 총 "해시 예산"이 일정하게 유지되도록 합니다. 공격자가 메시지 숫자를 더 큰 값(더 많은 해시 필요)으로 수정하면 체크섬 숫자는 자동으로 더 작아집니다(다른 값에서 더 적은 해시 필요, 이는 개인 키 없이는 위조 불가능).

### 키 생성 프로세스

Winternitz 매개변수 `w`가 있는 `n` 비트의 메시지 길이의 경우:

1. 서명 길이 계산: 먼저 메시지를 나타내는 데 필요한 "청크" 수를 파악합니다. 메시지 길이가 256비트이고 Winternitz 매개변수 `w = 4`를 선택하면 총 64청크가 필요합니다: `l₁ = ⌈n/w⌉`. 공식 `l₂ = ⌊log₂(l₁ × (2^w - 1))/w⌋ + 1`을 사용하면 최대 체크섬이 960인 `w = 4`의 경우 `l₂ = 3`이고 서명 크기는 `l = l₁ + l₂`가 됩니다.

> 키 생성 중에는 아직 서명할 메시지를 선택하지 않았기 때문에 체크섬이 무엇인지 알 수 없지만 체크섬을 위해 예약된 `l₂` 개인 키 구성 요소는 여전히 필요합니다.

2. 무작위 시작점 생성: 필요한 각 해시 체인에 대해 하나의 임의 비밀 값을 생성합니다. 이 임의 값은 개인 키 구성 요소가 됩니다. 각각을 별도 해시 체인의 "시작점"으로 생각하십시오: `sk = (sk₁, sk₂, ..., skₗ)`

3. 각 개인 키 구성 요소에 대해 최대 횟수(`2^w - 1`)까지 해시 함수를 반복적으로 적용합니다: `pk = (H^(2^w-1)(sk₁), H^(2^w-1)(sk₂), ..., H^(2^w-1)(skₗ))`

### 서명 프로세스

메시지 `M`에 서명하려면:

1. 메시지를 진수 표현으로 변환: `M → (m₁, m₂, ..., m_l₁)` 여기서 각 `mᵢ ∈ [0, 2^w - 1]`

2. 체크섬 계산: `c = Σ((2^w - 1) - mᵢ) for i = 1 to l₁` 그리고 c를 진수 표현으로 변환: `c → (c₁, c₂, ..., c_l₂)`

> 해당 메시지에 대한 실제 체크섬 값을 계산하기 위해 적절한 체크섬 개인 키 구성 요소를 사용하고 체크섬 숫자에 따라 올바른 횟수만큼 해시할 수 있습니다.

3. 서명 생성: 진수 표현이 개인 키를 해시해야 하는 횟수를 나타내는 곳입니다.

### 검증 프로세스

공개 키 `pk`로 메시지 `M`에 대한 서명 σ를 검증하려면:

1. 메시지 표현 재계산: `M → (m₁, m₂, ..., m_l₁)`

2. 체크섬 재계산: `c = Σ((2^w - 1) - mᵢ) → (c₁, c₂, ..., c_l₂)`

3. 각 서명 구성 요소에 대해 남은 횟수만큼 해시:
   - 메시지 부분의 경우: `H^((2^w-1)-mᵢ)(σᵢ) = pkᵢ` 검증
   - 체크섬 부분의 경우: `H^((2^w-1)-cⱼ)(σ_(l₁+j)) = pk_(l₁+j)` 검증

> 검증자는 서명자가 멈춘 곳에서 각 해시 체인을 "계속"하여 서명이 유효한 경우 알려진 공개 키 끝점에 도달합니다.

### 일회성 사용 제한

Winternitz 서명은 일회용 서명(OTS)입니다. 즉, 키 쌍당 한 번만 안전하게 사용할 수 있습니다.

공격은 다음과 같이 작동합니다: 동일한 개인 키로 여러 메시지에 서명하면 해시 체인의 중간 값이 드러납니다.

체크섬 메커니즘은 일부 메시지 숫자를 늘리는 것(더 많은 해시)이 체크섬 숫자를 줄이는 것(더 적은 해시)으로 균형을 맞춰야 합니다. 다른 위치에서 중간 값을 드러내는 여러 서명을 통해 공격자는 총 해시 예산 제약을 유지하면서 메시지 구성 요소에 대해 더 높은 곳으로 가기 위해 더 높은 중간 위치를 사용하고 체크섬 균형을 맞추기 위해 더 낮은 중간 위치를 사용하는 위조를 구성할 수 있습니다.

### 포스트 퀀텀 보안

Winternitz 서명은 해시 함수의 원형 저항성(preimage resistance)에서만 보안을 파생합니다. 양자 컴퓨터는 RSA 및 ECDSA를 깨는 다항 시간 양자 알고리즘(Shor 알고리즘)과 달리 SHA-256 또는 SHA-3과 같은 암호화 해시 함수를 효율적으로 역전시킬 수 없습니다.

적절한 매개변수와 함께 SHA-256을 사용하면 128비트의 포스트 퀀텀 보안을 제공하므로 포스트 퀀텀 세계에서도 장기 암호화 애플리케이션에 적합합니다.

<ArticleSection name="Solana의 Winternitz 서명" id="winternitz-on-solana" level="h2" />

Solana의 현재 암호화 기반은 전적으로 Ed25519 서명에 의존하며, 이는 Shor의 알고리즘을 통한 양자 공격에 취약합니다.

양자 컴퓨터가 실용화되면 Solana의 모든 지갑, 프로그램 권한 및 트랜잭션은 위조 가능해집니다.

포스트 퀀텀 전환은 하루아침에 할 수 있는 일이 아닙니다. 시스템은 오늘날 양자 저항성을 염두에 두고 설계되어야 하며, 프리 퀀텀(pre-quantum) 및 포스트 퀀텀 세계 모두에서 작동하는 하이브리드 접근 방식을 만들어야 합니다.

Solana의 기본 레이어는 양자 취약 상태로 남아 있지만 개발자는 Winternitz 서명을 사용하여 그 위에 양자 저항성 애플리케이션을 구축할 수 있습니다.
