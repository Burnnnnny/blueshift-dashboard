# PDA 공유 (PDA Sharing)

PDA 공유 공격은 여러 사용자 또는 도메인에서 동일한 프로그램 파생 주소(PDA)를 사용하는 프로그램을 악용하여 공격자가 자신에게 속하지 않은 자금, 데이터 또는 권한에 액세스할 수 있도록 합니다. 전역 PDA를 사용하는 것이 프로그램 전체 작업에 우아해 보일 수 있지만, 한 사용자의 작업이 다른 사용자의 자산에 영향을 줄 수 있는 위험한 교차 오염을 생성합니다.

취약점은 PDA를 파생할 때 시드 구체성이 불충분하기 때문에 발생합니다. 여러 계정이 동일한 PDA 권한을 공유하면 프로그램은 합법적인 액세스 시도와 불법적인 액세스 시도를 구별할 수 없게 됩니다. 공격자는 동일한 공유 PDA를 참조하는 자체 계정을 만든 다음 해당 PDA의 서명 권한을 사용하여 다른 사용자에게 속한 자산을 조작할 수 있습니다.

이는 PDA가 토큰 금고, 사용자 잔액 또는 인출 권한을 제어하는 DeFi 프로토콜에서 특히 치명적입니다. 공유 PDA는 본질적으로 여러 사용자의 자산을 잠금 해제하는 마스터 키를 생성하여 개별 사용자 작업을 전체 프로토콜에 대한 잠재적인 공격으로 전환합니다.

서명을 위해 민트 기반 PDA를 사용하는 이 취약한 인출 시스템을 고려하십시오:

```rust
#[program]
pub mod insecure_withdraw{
    use super::*;
    //..

    pub fn withdraw(ctx: Context<WithdrawTokens>) -> Result<()> {

        //..
        // other conditions/actions...
        //..

        let amount = ctx.accounts.vault.amount;
        
        let seeds = &[
            ctx.accounts.pool.mint.as_ref(),
            &[ctx.accounts.pool.bump],
        ];

        transfer(
            CpiContext::new_with_signer(
                ctx.accounts.token_program.to_account_info(),
                Transfer {
                    from: ctx.accounts.vault.to_account_info(),
                    to: ctx.accounts.withdraw_destination.to_account_info(),
                    authority: ctx.accounts.pool.to_account_info(),
                },
            ),
            &amount,
            seeds,
        )?;

        Ok(())
    }
        
    //..
}

#[derive(Accounts)]
pub struct WithdrawTokens<'info> {
    #[account(
        seeds = [b"pool", pool.mint.as_ref()],
        bump = pool.bump,                                        
    )]
    pool: Account<'info, TokenPool>,
    vault: Account<'info, TokenAccount>,
    withdraw_destination: Account<'info, TokenAccount>,
    //..
    // other accounts..
    //..
    token_program: Program<'info, Token>,
}

#[account]
#[derive(InitSpace)]
pub struct TokenPool {
    pub mint: Pubkey,
    pub bump: u8,
}
```

이 코드에는 치명적인 결함이 있습니다. PDA는 민트 주소만 사용하여 파생됩니다. 즉, 동일한 토큰 유형에 대한 모든 금고가 동일한 서명 권한을 공유하므로 위험한 공격 벡터가 생성됩니다.

공격자는 다음을 통해 이를 악용할 수 있습니다:
- 동일한 민트에 대해 자신의 금고 생성
- 자신의 주소를 `withdraw_destination`으로 하여 명령어 호출
- 공유된 PDA 권한을 사용하여 동일한 민트를 사용하는 모든 금고에서 토큰 인출
- 다른 사용자의 자금을 자신의 목적지로 고갈

PDA 권한이 다른 풀 인스턴스를 구별하지 않고 해당 자금에 액세스해야 하는 특정 사용자가 아니라 민트 유형에만 신경 쓰기 때문에 공격이 성공합니다.

가능한 해결책은 PDA를 개별 사용자 및 목적지에 고유하게 만들고 Anchor의 시드 및 범프 제약 조건을 사용하여 PDA 파생을 검증하는 것입니다:

```rust
#[derive(Accounts)]
pub struct WithdrawTokens<'info> {
    #[account(
        has_one = vault,
        has_one = withdraw_destination,
        seeds = [b"pool", vault.key().as_ref(), withdraw_destination.key().as_ref()],
        bump = pool.bump,                                        
    )]
    pool: Account<'info, TokenPool>, // 금고에 대한 권한
    #[account(mut)]
    vault: Account<'info, TokenAccount>,
    #[account(mut)]
    withdraw_destination: Account<'info, TokenAccount>,
    //..
    // other accounts..
    //..
    token_program: Program<'info, Token>,
}

#[account]
#[derive(InitSpace)]
pub struct TokenPool{
    pub vault:Pubkey,
    pub withdraw_destination:Pubkey,
    pub bump:u8
}
```

명령어 핸들러에 대해서도 동일한 변경이 이루어집니다. 이것이 유효할 수 있는 한 가지 가능한 상황은 사용자가 일정 금액을 잃었을 때 거래가 청산되도록 허용하는 레버리지 거래 프로그램입니다. 예를 들어 사용자가 스스로 손절매를 설정하면 코드는 해당 금액에 도달하는 조건을 확인한 다음 누구든지 거래를 중지하고 남은 자금을 목적지인 인출 계정으로 인출할 수 있도록 허용합니다.

특정 민트에 대한 모든 자금을 제어하는 단일 PDA는 동시에 여러 사용자에 대한 조건이 충족되는 경우(예: 많은 사용자가 손절매/청산에 가까운 경우) 상황을 만들 수 있으며, 단일 사용자는 다른 사용자를 위해 이 작업을 수행하는 여러 명령어를 포함하는 하나 이상의 트랜잭션에서 모든 사용자에 대해 해당 자금을 인출할 수 있습니다.
