# 프로그램 보안 (Program Security)

![Program Security](/graphics/course-banners/program-security.png)

> 이 과정에 대한 초기 콘텐츠를 개척하고 가이드를 통해 구체화한 [Unboxed Software](https://x.com/unboxedsoftware)에 큰 감사를 표합니다!

매일 수백만 달러가 Solana 프로그램을 통해 빛의 속도로 흐릅니다. 이렇게 위험 부담이 크고 성능이 뛰어난 환경에서는 취약한 코드 한 줄이 몇 초 만에 프로토콜을 고갈시킬 수 있는 반면, 잘 보안된 프로그램은 땀 한 방울 흘리지 않고 초당 수천 건의 트랜잭션을 처리할 수 있습니다.

Solana의 혁신적인 병렬 처리 아키텍처는 다른 블록체인보다 빠를 뿐만 아니라 근본적으로 다릅니다.

Ethereum 개발자가 가스 최적화 및 순차 실행에 대해 걱정하는 동안, Solana 개발자는 계정이 스토리지를 대체하고 프로그램이 비저장이며 트랜잭션이 병렬 실행 레인에서 서로 경쟁하는 완전히 새로운 위협 환경을 마스터해야 합니다.

Solana 블록체인 개발에 고유한 보안 악용 사례가 많이 있습니다. 이 과정에서는 실제 사례와 실용적인 완화 전략을 통합하여 [Coral의 Sealevel Attack 리포지토리](https://github.com/coral-xyz/sealevel-attacks)를 모델로 한 모든 Sealevel 공격을 배웁니다.

프로그램을 메인넷에 배포하기 전에 보안 기본 사항에 대한 최소한의 기본적인 이해가 있어야 합니다.

> 동일한 악용 사례가 Native 및 Anchor 개발 모두에 "유효"합니다.

<ArticleSection name="프로그램 보안 소개" id="introduction-to-program-security" level="h2" />

Solana 개발에서 가장 중요한 보안 고려 사항은 플랫폼의 계정 소유권 모델과 프로그램이 계정과 상호 작용하는 방식에서 비롯됩니다.

프로그램은 계정 소유권을 신중하게 검증하고 적절한 액세스 제어를 구현하며 프로그램 간 호출(CPI)의 복잡성을 처리해야 합니다.

프로그램의 비저장 특성은 악의적인 계정 조작에 대한 기본 제공 보호 기능이 없으므로 모든 검증 로직을 명시적으로 구현해야 함을 의미합니다.

또한 Solana 프로그램의 일반적인 취약점 패턴에는 누락된 소유권 확인, 불충분한 서명자 검증, 산술 오버플로/언더플로, 계정 초기화 및 폐쇄의 부적절한 처리가 포함됩니다.

> Anchor는 개발자가 특정 유형을 사용하거나 프로그램에 대해 신중한 선택을 하도록 강제하여 Solana 프로그램을 더 안전하게 만든다는 아이디어로 개발되었습니다.

각 보안 취약점이 언뜻 보기에 "간단해" 보일 수 있지만 각 시나리오에서 논의할 상당한 깊이가 있습니다. 이 수업에는 산문이 적고 실용적인 코드 예제가 더 많이 포함되어 있어 논의된 보안 위험에 대한 확실하고 실질적인 이해를 얻을 수 있습니다.

Solana 보안 지식을 향상시킬 준비가 되셨습니까? 더 안전한 프로그램을 함께 구축해 봅시다.
