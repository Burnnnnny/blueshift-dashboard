# 부활 공격 (Revival Attacks)

부활 공격은 동일한 트랜잭션 내에서 "죽은" 계정을 되살려 Solana의 계정 폐쇄 메커니즘을 악용합니다.

lamport를 전송하여 계정을 닫으면 Solana는 즉시 가비지 수집을 수행하지 않습니다. 계정은 트랜잭션이 완료된 후에만 정리됩니다. 이러한 지연은 공격자가 닫힌 계정으로 lamport를 다시 보내 계정을 "부활"시켜 프로그램이 여전히 신뢰할 수 있는 오래된 데이터가 있는 좀비 계정을 남길 수 있는 위험한 창을 만듭니다.

이 공격은 계정 수명 주기에 대한 기본적인 오해 때문에 성공합니다. 개발자는 계정을 닫으면 즉시 사용할 수 없게 된다고 가정하지만 실제로는 트랜잭션이 종료될 때까지 계정에 액세스할 수 있습니다. 공격자는 닫기 명령어를 임대 면제를 환불하는 전송으로 샌드위치하여 가비지 수집을 방지하고 계정을 악용 가능한 상태로 유지할 수 있습니다.

이는 에스크로 완료, 분쟁 해결 또는 자산 소각과 같이 계정 폐쇄가 완료를 나타내는 프로토콜에서 특히 치명적입니다. 부활된 계정은 이러한 작업이 완료되지 않았다고 믿도록 프로그램을 속여 이중 지출, 무단 액세스 또는 프로토콜 조작을 허용할 수 있습니다.

프로그램 계정을 닫는 이 취약한 명령어를 고려하십시오:

```rust
#[program]
pub mod insecure_close{
    use super::*;

    //..

    pub fn close(ctx: Context<Close>) -> Result<()> {
        let dest_starting_lamports = ctx.accounts.destination.lamports();

        **ctx.accounts.destination.lamports.borrow_mut() = dest_starting_lamports
            .checked_add(ctx.accounts.account_to_close.to_account_info().lamports())
            .unwrap();
        **ctx.accounts.account_to_close.to_account_info().lamports.borrow_mut() = 0;

        Ok(())
    }
        
    //..
}

#[derive(Accounts)]
pub struct Close<'info> {
    /// CHECK: This account will not be checked by Anchor
    pub owner: UncheckedAccount<'info>,
   #[account(
        mut,
        has_one = owner
    )]
    pub program_account: Account<'info, ProgramAccount>,

}
```

이 코드는 올바르게 보입니다. 계정의 모든 lamport를 대상으로 전송하여 가비지 수집을 트리거해야 합니다. 그러나 계정 데이터는 손대지 않은 상태로 유지되며 동일한 트랜잭션 내에서 계정에 여전히 액세스할 수 있습니다.

공격자는 여러 명령어가 포함된 트랜잭션을 생성하여 이를 악용할 수 있습니다:
- 명령어 1: 닫기 함수를 호출하여 계정의 lamport 고갈
- 명령어 2: "닫힌" 계정으로 lamport 다시 전송 (부활)
- 명령어 3: 후속 작업에서 부활된 계정 사용

결과는 프로그램 로직에는 닫힌 것처럼 보이지만 모든 원본 데이터가 그대로 유지된 채 기능하는 좀비 계정입니다. 이로 인해 다음이 발생할 수 있습니다:
- 이중 지출: "닫힌" 에스크로 계정 여러 번 사용
- 권한 우회: 비활성화되어야 하는 관리자 계정 부활
- 상태 손상: 더 이상 존재해서는 안 되는 계정에서 작업

가장 안전한 해결책은 안전한 폐쇄를 자동으로 처리하는 Anchor의 `close` 제약 조건을 사용하는 것입니다:

```rust
#[derive(Accounts)]
pub struct Close<'info> {
    #[account(mut)]
    pub owner: Signer<'info>,
   #[account(
        mut,
        close = owner,
        has_one = owner
    )]
    pub program_account: Account<'info, ProgramAccount>,
}
```

또는 다음과 같이 `signer` 계정 제약 조건을 추가할 수 있습니다:

```rust
#[derive(Accounts)]
pub struct Close<'info> {
    #[account(signer)]
    /// CHECK: This account will not be checked by Anchor
    pub owner: UncheckedAccount<'info>,
    /// CHECK: This account will not be checked by Anchor
    pub new_owner: UncheckedAccount<'info>,
   #[account(
        mut,
        has_one = owner
    )]
    pub program_account: Account<'info, ProgramAccount>,
}
```

사용자 지정 폐쇄 로직의 경우 전체 보안 폐쇄 패턴을 구현하십시오:

```rust
pub fn update_ownership(ctx: Context<UpdateOwnership>) -> Result<()> {
    let account = ctx.accounts.account.to_account_info();

    let dest_starting_lamports = ctx.accounts.destination.lamports();

    **ctx.accounts.destination.lamports.borrow_mut() = dest_starting_lamports
        .checked_add(account.lamports())
        .unwrap();
    **account.lamports.borrow_mut() = 0;

    let mut data = account.try_borrow_mut_data()?;
    for byte in data.deref_mut().iter_mut() {
        *byte = 0;
    }

    let dst: &mut [u8] = &mut data;
    let mut cursor = std::io::Cursor::new(dst);
    cursor
        .write_all(&anchor_lang::__private::CLOSED_ACCOUNT_DISCRIMINATOR)
        .unwrap();

    Ok(())
}
```
