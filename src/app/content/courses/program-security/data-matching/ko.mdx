# 데이터 일치 (Data Matching)

데이터 일치는 프로그램 로직에서 신뢰하기 전에 계정 데이터에 예상 값이 포함되어 있는지 확인하는 보안 관행입니다. `owner` 확인이 계정을 제어하는 사람을 확인하고 `signer` 확인이 권한을 확인하는 동안, 데이터 일치는 계정의 내부 상태가 프로그램의 가정과 일치하는지 확인합니다.

이는 명령어 핸들러가 계정 간의 관계에 의존하거나 특정 데이터 값이 프로그램 동작을 결정할 때 중요합니다. 적절한 데이터 검증이 없으면 공격자는 계정이 기본 소유권 및 권한 확인을 통과하더라도 예상치 못한 데이터 조합으로 계정을 조작하여 프로그램 흐름을 조작할 수 있습니다.

위험은 구조적 검증과 논리적 검증 사이의 격차에 있습니다. 프로그램은 계정에 올바른 유형이 있고 올바른 프로그램이 소유하고 있음을 올바르게 확인할 수 있지만, 서로 다른 데이터 부분 간의 관계에 대해 여전히 잘못된 가정을 할 수 있습니다.

<ArticleSection name="Anchor" id="anchor" level="h2" />

프로그램 계정의 소유권을 업데이트하는 이 취약한 명령어를 고려하십시오:

```rust
#[program]
pub mod insecure_update{
    use super::*;
    //..

    pub fn update_ownership(ctx: Context<UpdateOwnership>) -> Result<()> {
        ctx.accounts.program_account.owner = ctx.accounts.new_owner.key();
    
        Ok(())
    }

    //..
}

#[derive(Accounts)]
pub struct UpdateOwnership<'info> {
    pub owner: Signer<'info>,
    /// CHECK: This account will not be checked by Anchor
    pub new_owner: UncheckedAccount<'info>,
   #[account(mut)]
    pub program_account: Account<'info, ProgramAccount>,
}

#[account]
pub struct ProgramAccount {
    owner: Pubkey,
}
```

이 코드는 언뜻 보기에 안전해 보입니다. `owner`는 `Signer`로 적절하게 표시되어 트랜잭션을 승인했음을 보장합니다. `program_account`는 올바르게 입력되었으며 프로그램이 소유합니다. 모든 기본 보안 검사가 통과됩니다.

그러나 치명적인 결함이 있습니다. 프로그램은 트랜잭션에 서명한 `owner`가 실제로 `program_account` 데이터에 저장된 `owner`와 동일한지 확인하지 않습니다.

공격자는 다음을 통해 이를 악용할 수 있습니다:
- 자신의 키 쌍 생성 (`attacker_keypair`라고 합시다)
- 탈취하려는 프로그램 계정 찾기
- 다음과 같은 트랜잭션 제작: `owner`는 `attacker_keypair`(자신이 제어하고 서명할 수 있음); `new_owner`는 자신의 메인 공개 키이고 `program_account`는 피해자의 계정입니다.

`attacker_keypair`가 적절하게 서명하기 때문에 트랜잭션이 성공하지만, 프로그램은 `attacker_keypair`가 `program_account.owner`에 저장된 실제 `owner`와 일치하는지 확인하지 않습니다. 공격자는 다른 사람 계정의 소유권을 성공적으로 자신에게 이전합니다.

다행히 `Anchor`를 사용하면 다음과 같이 `has_one` 제약 조건을 추가하여 계정 구조체에서 직접 이 검사를 매우 쉽게 수행할 수 있습니다:

```rust
#[derive(Accounts)]
pub struct UpdateOwnership<'info> {
    pub owner: Signer<'info>,
    /// CHECK: This account will not be checked by Anchor
    pub new_owner: UncheckedAccount<'info>,
   #[account(mut, has_one = owner)]
    pub program_account: Account<'info, ProgramAccount>,
}
```

또는 프로그램의 디자인을 변경하고 `program_account`를 다음과 같이 `owner`에서 파생된 PDA로 만들기로 결정할 수 있습니다:

```rust
#[derive(Accounts)]
pub struct UpdateOwnership<'info> {
    pub owner: Signer<'info>,
    /// CHECK: This account will not be checked by Anchor
    pub new_owner: UncheckedAccount<'info>,
   #[account(
        mut,
        seeds = [owner.key().as_ref()],
        bump
    )]
    pub program_account: Account<'info, ProgramAccount>,
}
```

또는 다음과 같이 `ctx.accounts.program_account.owner` 확인을 사용하여 명령어에서 해당 데이터를 확인할 수 있습니다:

```rust
pub fn update_ownership(ctx: Context<UpdateOwnership>) -> Result<()> {
    if ctx.accounts.program_account.owner != ctx.accounts.owner.key() {
        return Err(ProgramError::InvalidAccountData.into());
    }

    ctx.accounts.program_account.owner = ctx.accounts.new_owner.key();
    
    Ok(())
}
```

이 확인을 추가하면 계정에 올바른 `owner`가 있는 경우에만 명령어 핸들러가 진행됩니다. `owner`가 올바른 것이 아니면 트랜잭션이 실패합니다.

<ArticleSection name="Pinocchio" id="pinocchio" level="h2" />

Pinocchio에서는 계정 구조체 내부에 보안 검사를 직접 추가할 수 없으므로 명령어 로직에서 수행해야 합니다.

계정 데이터를 역직렬화하고 `owner` 값을 확인하여 이를 수행할 수 있습니다:

```rust
let account_data = ctx.accounts.program_account.try_borrow_data()?;
let mut account_data_slice: &[u8] = &account_data;
let account_state = ProgramAccount::try_deserialize(&mut account_data_slice)?;

if account_state.owner != self.accounts.owner.key() {
    return Err(ProgramError::InvalidAccountData.into());
}
```

> Pinocchio를 사용하면 원하는 대로 역직렬화 및 직렬화를 처리할 수 있으므로 `ProgramAccount::try_deserialize()` 함수를 만들어야 합니다.
