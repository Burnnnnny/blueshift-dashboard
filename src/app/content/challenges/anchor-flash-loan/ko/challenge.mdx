# Anchor 플래시 론 (Anchor Flash Loan)

![Anchor Flash Loan](/graphics/challenge-banners/anchor-flash-loan.png)

명령어 인트로스펙션(Instruction introspection)은 블록체인 프로그램이 동일한 트랜잭션 번들 내의 다른 명령어를 검사하고 분석할 수 있게 해주는 강력한 기능입니다. 여기에는 아직 실행되지 않은 명령어도 포함되므로 프로그램이 "미리 보고" 나중에 트랜잭션에서 발생할 일을 기반으로 결정을 내릴 수 있는 기능을 제공합니다.

트랜잭션에 대한 X-ray 비전을 갖는 것과 같다고 생각하면 됩니다. 프로그램은 전체 트랜잭션을 꿰뚫어 보고 전체 작업 순서를 이해한 후 진행 방법을 결정할 수 있습니다.

명령어 인트로스펙션의 가장 강력한 응용 사례는 플래시 론(Flash Loan)입니다. 이는 단일 트랜잭션의 경계 내에서만 존재하는 독특한 유형의 대출입니다.

플래시 론의 작동 방식은 다음과 같습니다:
- **대출 (Borrow)**: 트랜잭션 시작 시 `loan` 명령어를 사용하여 대규모 자본을 즉시 빌릴 수 있습니다.
- **사용 (Use)**: 이 빌린 자본을 동일한 트랜잭션 내에서 거래, 차익 거래 또는 기타 작업에 사용할 수 있습니다.
- **상환 (Repay)**: 트랜잭션이 끝나기 전에 `repay` 명령어를 사용하여 대출금과 소정의 수수료를 상환해야 합니다.

핵심 통찰력은 플래시 론이 블록체인 트랜잭션의 원자성(atomic nature)에 의존한다는 것입니다. 트랜잭션의 일부라도 실패하면(상환 포함) 전체 트랜잭션이 마치 처음부터 발생하지 않은 것처럼 롤백됩니다. 이는 대출 기관에 위험이 전혀 없음을 의미합니다. 상환을 받거나 대출이 실제로 발생하지 않거나 둘 중 하나입니다.

이 챌린지에서는 명령어 인트로스펙션이 실제로 작동하는 것을 보여주는 간단한 플래시 론 프로그램을 만들 것입니다. 이 프로그램은 동일한 트랜잭션 내의 다른 명령어에 걸쳐 명령어 데이터와 계정을 검사하여 대출 조건이 충족되도록 합니다.

명령어 인트로스펙션을 처음 접하는 경우 이 프로그램에서 사용되는 기본 개념을 이해하기 위해 [명령어 인트로스펙션 과정](/ko/courses/instruction-introspection)으로 시작하는 것이 좋습니다.

<ArticleSection name="설치" id="installation" level="h2" />

시작하기 전에 Rust와 Anchor가 설치되어 있는지 확인하세요. 설정 지침이 필요한 경우 [공식 anchor 문서](https://www.anchor-lang.com/docs/installation)를 참조하세요. 그런 다음 터미널에서 다음을 실행합니다:

```bash
anchor init blueshift_anchor_flash_loan
```

필요한 종속성 추가:
- `anchor-spl`: SPL 토큰(Solana의 토큰 표준) 작업을 위한 유틸리티를 제공합니다.

```bash
cd blueshift_anchor_flash_loan
cargo add anchor-spl
```

이제 플래시 론 프로그램 구축을 시작할 준비가 되었습니다!

<ArticleSection name="템플릿" id="template" level="h2" />

`borrow` 및 `repay` 명령어가 모두 사용할 기본 구조, 계정 및 오류 처리를 설정하여 플래시 론 프로그램의 기초를 구축해 보겠습니다.

동일한 계정 구조를 공유하는 두 가지 명령어만 있으므로 `lib.rs`에서 모든 것을 구현할 것입니다. 모든 필수 구성 요소가 있는 시작 템플릿은 다음과 같습니다:

<ArticleSection name="계정 (Accounts)" id="accounts" level="h2" />

`borrow` 및 `repay` 명령어가 모두 동일한 계정으로 작동하므로 두 기능을 모두 수행하는 단일 `Loan` 컨텍스트를 만들 수 있습니다. 이렇게 하면 코드를 더 유지 관리하기 쉽고 이해하기 쉽게 만들 수 있습니다.

`Loan` 계정 구조체에는 다음 구성 요소가 필요합니다:
- `borrower`: 플래시 론을 요청하는 사용자.
- `protocol`: 프로토콜의 유동성 풀을 소유하는 PDA(Program Derived Address).
- `mint`: 대출되는 특정 토큰.
- `borrower_ata`: 빌린 토큰을 받을 대출자의 연결된 토큰 계정(ATA).
- `protocol_ata`: 빌린 토큰을 제공할 프로토콜의 연결된 토큰 계정.
- `instructions`: 인트로스펙션을 위한 Instructions Sysvar 계정.
- `token_program`, `associated_token_program`, 및 `system_program`: 프로그램에 필요한 프로그램들.

계정 구조체를 정의하는 방법은 다음과 같습니다:

```rust
#[derive(Accounts)]
pub struct Loan<'info> {
  #[account(mut)]
  pub borrower: Signer<'info>,
  #[account(
    seeds = [b"protocol".as_ref()],
    bump,
  )]
  pub protocol: SystemAccount<'info>,

  pub mint: Account<'info, Mint>,
  #[account(
    init_if_needed,
    payer = borrower,
    associated_token::mint = mint,
    associated_token::authority = borrower,
  )]
  pub borrower_ata: Account<'info, TokenAccount>,
  #[account(
    mut,
    associated_token::mint = mint,
    associated_token::authority = protocol,
  )]
  pub protocol_ata: Account<'info, TokenAccount>,

  #[account(address = INSTRUCTIONS_SYSVAR_ID)]
  /// CHECK: InstructionsSysvar account
  instructions: UncheckedAccount<'info>,
  pub token_program: Program<'info, Token>,
  pub associated_token_program: Program<'info, AssociatedToken>,
  pub system_program: Program<'info, System>
}
```

보시다시피 이 명령어와 해당 제약 조건에 필요한 계정은 매우 간단합니다:
- `protocol`: `seeds = [b"protocol".as_ref()]`를 사용하여 모든 프로토콜 유동성을 소유하는 결정적 주소를 생성합니다. 이렇게 하면 프로그램만이 자금을 제어할 수 있습니다.
- `borrower_ata`: 대출자가 아직 이 특정 토큰에 대한 연결된 토큰 계정이 없을 수 있으므로 `init_if_needed`를 사용합니다. 제약 조건은 필요한 경우 자동으로 생성합니다.
- `protocol_ata`: 여기서 토큰을 전송할 것이므로 이미 존재하고 변경 가능해야 합니다. `associated_token::authority = protocol` 제약 조건은 프로토콜 PDA만이 전송을 승인할 수 있도록 보장합니다.
- `instructions`: 트랜잭션 명령어 데이터가 포함된 올바른 시스템 계정에 액세스하고 있는지 확인하기 위해 `address` 제약 조건을 사용합니다.

<ArticleSection name="오류 (Errors)" id="errors" level="h2" />

플래시 론은 여러 단계에서 정밀한 검증이 필요하므로 포괄적인 오류 처리가 필요합니다. 전체 오류 열거형은 다음과 같습니다:

```rust
#[error_code]
pub enum ProtocolError {
    #[msg("Invalid instruction")]
    InvalidIx,
    #[msg("Invalid instruction index")]
    InvalidInstructionIndex,
    #[msg("Invalid amount")]
    InvalidAmount,
    #[msg("Not enough funds")]
    NotEnoughFunds,
    #[msg("Program Mismatch")]
    ProgramMismatch,
    #[msg("Invalid program")]
    InvalidProgram,
    #[msg("Invalid borrower ATA")]
    InvalidBorrowerAta,
    #[msg("Invalid protocol ATA")]
    InvalidProtocolAta,
    #[msg("Missing repay instruction")]
    MissingRepayIx,
    #[msg("Missing borrow instruction")]
    MissingBorrowIx,
    #[msg("Overflow")]
    Overflow,
}
```

이 기초가 마련되었으므로 플래시 론 명령어의 핵심 로직을 구현할 준비가 되었습니다. 계정 구조는 적절한 토큰 처리를 보장하는 반면 오류 시스템은 디버깅 및 보안 검증을 위한 명확한 피드백을 제공합니다.
